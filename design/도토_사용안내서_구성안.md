# 도토 사용안내서 구성안

작성일: 2026-09-11  
목적: 학생과 교사가 실제 수업 순서대로 따라가는, 화면 캡처와 화살표 중심의 안내서 설계.

## 1. 구성 방향

**학생 편과 교사 편을 따로 읽을 수 있게 만들고, 각 편의 앞부분은 첫 수업을 따라가는 순서로 구성한다.** 뒤에는 다시 찾아볼 상황별 안내를 둔다. 한 장의 목표는 한 가지로 제한한다.

- 학생 편: 입장 → 주제 선택·쓰기 → 피드백 읽고 고치기 → 게시 → 친구 글 읽기·댓글.
- 교사 편: 수업 열기 → 필요하면 PC 연결 → 주제 준비 → 학생 초대 → 전체 원고 관찰 → 개별 지도 → 함께 읽기 → 종료·보관 → 다음 수업.
- 학생의 이어 쓰기·도움 요청·수정본 재게시, 교사의 자료 설정·그룹 정리·연결 문제는 해당 단계에서 찾아갈 수 있게 연결한다.
- 실제 사용법과 수업 진행 아이디어를 구별한다. 예를 들어 ‘이유가 드러난 문장에 댓글 쓰기’는 교사의 수업 제안이지, 프로그램이 강제하는 절차가 아니다.

권장 형태는 **가로 화면형 안내서**다. 학생 편은 별도 파일로도 배포하고, 첫 수업에서는 필요한 장만 교실 화면에 띄운다. 공통 1장 + 학생 8장 + 교사 11장으로 기본 구성을 잡고, 상황별 부록을 더한다. 장수보다 버튼과 문장이 읽히는 크기를 우선한다. 표지와 별도 목차는 최종 편집 시 추가할 수 있다.

## 2. 워크플로우 분석

### 학생: 자신의 글을 시작하고, 고치고, 나누는 과정

| 단계 | 학생이 해결하려는 일 | 실제 화면·행동 | 다음 단계로 넘어가는 기준 |
| --- | --- | --- | --- |
| 입장 | 내 이름으로 우리 반에 들어가기 | 학생용 QR 또는 방 입장하기 → 6자리 코드 → 이름 또는 별명 | 자기 이름과 우리 반 게시판이 보임 |
| 시작 | 어느 주제에 쓸지 정하기 | 그룹 제목·안내 확인 → 해당 그룹의 + | 선택한 주제가 표시된 새 원고가 열림 |
| 작성 | 제목과 본문 쓰기 | 글 제목·본문 입력, 필요하면 수업 도움 보기 | 제목·본문이 있고 ‘이 기기에 저장됨’ 표시 |
| 지도받기 | 막힌 부분을 해결하기 | 도움 요청 또는 메시지, 교사 피드백 확인 | 질문에 답을 받거나 수정할 부분을 이해함 |
| 수정 | 교사 의견을 읽고 내 글 고치기 | 노란 구절 또는 피드백 → 본문 수정 → 고쳤어요 | 교사가 수정 확인을 할 수 있는 상태가 됨 |
| 공개 | 친구들이 읽도록 올리기 | 게시하기 | 게시판으로 이동하고 내 글 카드가 나타남 |
| 교류 | 친구의 글을 읽고 반응하기 | 펼치기/글 읽기 → 댓글 → 남기기 | 댓글이 실제 목록에 나타남 |
| 이어가기 | 쓰던 글이나 게시한 글을 다시 고치기 | 미게시 원고는 내가 쓰던 글 → 이어 쓰기. 게시한 글은 수정 후 수정한 글 게시하기 | 기존 원고를 이어 쓰거나 공개본이 새 내용으로 바뀜 |

이 과정은 항상 일직선은 아니다. 작성과 수정은 반복되고, 도움 요청은 쓰는 도중에 갈라지는 경로다. 교사 피드백을 받지 않아도 게시할 수 있으므로, 안내서에서 피드백이나 교사 확인을 게시의 필수 승인 절차처럼 표현하지 않는다.

### 교사: 수업을 유지하며 원고를 살피고 지도하는 과정

| 단계 | 교사가 해결하려는 일 | 실제 화면·행동 | 안내에서 강조할 점 |
| --- | --- | --- | --- |
| 연결 준비 | 학생용 태블릿 중 한 대를 수업 유지 기기로 준비하기 | 학생들이 쓰는 와이파이에 연결한 학생용 태블릿에서 dotoschool.uk → 수업 열기 | 이 태블릿의 도토 화면을 수업 끝까지 켜 둠 |
| 작업 환경 | 큰 화면에서 지도하기 | 필요하면 다른 PC에서 8자리 교사용 코드로 입장 | 수업을 연 기기와 지도용 PC의 역할을 구분 |
| 수업 준비 | 학생이 쓸 주제와 안내 만들기 | 게시판 → 그룹 만들기/그룹 설정 | 그룹은 글을 모으는 주제 칸. 자동으로 학생을 배정하는 모둠 기능으로 설명하지 않음 |
| 학생 초대 | 학생이 자기 이름으로 들어왔는지 확인하기 | 학생용 코드·QR 안내 → 참여 학생·연결 상태 확인 | 참여 학생 수와 원고 수는 다름 |
| 관찰 | 누가 무엇을 쓰는지 보기 | 전체 글 → 원고 없음/초안/도움 요청 등 → 원고 상세 | 게시하기 전 원고도 볼 수 있음 |
| 지도 | 문장에 의견을 남기고 질문에 답하기 | 구절 선택 → 피드백 하기, 글 전체 피드백, 도움 요청·메시지 응답 | 구절 피드백·전체 피드백·대화의 위치와 용도를 구분 |
| 재확인 | 학생이 고친 내용을 확인하기 | 고친 글 확인 → 원고 읽기 → 확인 완료/다시 살펴봐요 | ‘고쳤어요’는 학생의 응답 표시. 자동 수정 검증이나 점수가 아님 |
| 공유 | 완성 글을 함께 읽기 | 게시판 → 글 펼치기/읽기 → 댓글 운영 | 전체 글은 지도용, 게시판은 공유용이라는 목적 차이를 보여 줌 |
| 마무리 | 수업을 닫고 결과를 간직하기 | 수업을 연 기기에서 수업 마치기 → 지난 수업 → 결과 내보내기 | PC 연결 나가기는 수업 종료와 다름 |
| 다음 시간 | 지난 글을 이어서 수업하기 | 지난 수업 → 다시 수업 열기 → 새 코드 안내 | 같은 기기·브라우저·주소의 보관함을 사용 |

교사의 핵심 반복은 **전체 글 → 개별 원고 → 피드백/답장 → 전체 글 → 고친 글 확인**이다. 수업 개설이나 설정 화면보다 이 반복에 큰 캡처와 설명 공간을 배정한다.

### 두 역할이 만나는 장면

| 학생 쪽 | 교사 쪽 | 안내서에서 연결할 페이지 |
| --- | --- | --- |
| 제목·본문을 쓰는 중 | 전체 글에 작성 중인 원고가 보임 | S02 ↔ T05 |
| 도움 요청/메시지를 보냄 | 도움 요청/새 메시지에서 해당 글을 찾음 | S07 ↔ T07 |
| 노란 구절의 피드백을 읽음 | 문장을 선택해 피드백을 보냄 | S03 ↔ T06 |
| 고쳤어요를 누름 | 고친 글 확인 → 확인 완료 | S03 ↔ T08 |
| 게시하기를 누름 | 게시판에서 함께 읽기 | S04 ↔ T09 |

## 3. 공통 첫 장

### C01. 도토에서는 이렇게 글을 나눠요

- 학생 줄: 들어오기 → 쓰기 → 고치기 → 게시하기 → 함께 읽기.
- 교사 줄: 수업 준비 → 원고 살피기 → 피드백 → 함께 읽기 → 결과 보관.
- 글쓰기 화면과 게시판 화면을 작은 캡처 두 개로 연결한다.
- 핵심 문구: **‘쓰는 중에는 나와 선생님이 봐요. 게시하면 수업에 참여한 친구들도 읽어요.’**
- 이 페이지에서 학생 편 / 교사 편으로 바로 이동하게 한다.

기기 연결 구조는 교사 편에 둔다. 학생용 첫 장에는 코드를 발급하는 방법이나 서버 구조를 넣지 않는다.

## 4. 학생 편 — 페이지 순서와 캡처 설계

S01~S05는 첫 글을 완성하는 순서다. S06~S08은 필요한 순간 찾아보는 페이지이며, 관련 기본 페이지 아래에 바로가기 표시를 둔다.

| 페이지·제목 | 캡처할 상태 | 화살표·번호로 짚을 곳 | 한 줄 설명·완료 모습 |
| --- | --- | --- | --- |
| **S01 우리 반에 들어가요** | 6자리 코드를 넣어 이름 칸이 나타난 입장 화면 | ① 학생용 코드 ② 이름 또는 별명 ③ 방 입장하기 | ‘선생님이 알려 준 이름으로 들어와요.’ 완료: 자기 이름이 보이는 게시판을 작은 캡처로 제시. QR 입장은 ‘코드가 미리 들어 있어요’ 보조 경로로 표시 |
| **S02 주제를 고르고 글을 써요** | 왼쪽에 게시판의 그룹 일부, 오른쪽에 열린 글쓰기 화면 | ① 주제 아래 + ② 제목 ③ 본문 | ‘이 주제에 내 이야기를 써요.’ 저장 표시는 클릭 화살표 대신 확대 상자로 제시. 수업 도움 보기·자료는 부록 A01 연결 |
| **S03 선생님 말을 읽고 고쳐요** | 노란 구절과 피드백 카드가 함께 보이는 원고 | ① 노란 구절/피드백 ② 고칠 본문 ③ 고쳤어요 | ‘글을 고친 다음 눌러요.’ 읽었어요는 읽음 표시, 고쳤어요는 수정 후 교사에게 알리는 표시로 구분. 이미 게시한 글이면 S08 연결 |
| **S04 친구들에게 글을 보여 줘요** | 게시하기 직전 원고 상단 → 게시 후 자기 글 카드 | ① 제목·본문 확인 ② 게시하기 ③ 게시판의 내 글 | ‘게시하면 친구들도 읽을 수 있어요.’ 자동 저장과 공개를 한 번 더 구분. 게시 버튼이 활성화된 상태와 결과 화면을 함께 사용 |
| **S05 친구 글을 읽고 댓글을 남겨요** | 게시판 카드 일부 → 열린 글의 댓글 영역 | ① 친구 글 읽기 ② 댓글 입력 ③ 남기기 | 댓글 예시: ‘네 경험을 넣어서 마음이 잘 전해졌어.’ 완료: 작성한 댓글이 목록에 나타난 모습. 펼치기는 긴 글 읽기의 보조 동작으로 표시 |
| **S06 쓰던 글을 이어 써요** | 원고의 저장 표시·게시판으로 버튼 → 게시판의 내가 쓰던 글 | ① 이 기기에 저장됨 확인 ② 게시판으로 ③ 이어 쓰기 | ‘새 글을 만들지 않고 쓰던 글을 열어요.’ 같은 기기·브라우저·주소로 다시 들어오는 조건을 한 줄로 안내 |
| **S07 막히면 선생님께 알려요** | 도움·메시지를 펼친 화면과 요청 창/대화 창 | 두 갈래로 구분: ‘와서 도와주세요’ → 선생님께 도움 요청 / ‘글로 질문해요’ → 메시지 보내기 | 한 경로를 세 단계로 크게 보여 주고 다른 경로는 작은 보조 상자로 둠. 새 답장 표시도 확대. 잘못 고른 주제는 ‘다른 그룹으로 옮겨 주세요’ 연결 |
| **S08 게시한 글을 다시 고쳐요** | 자기 게시글의 수정 진입 → 수정된 원고 상단 → 바뀐 게시글 | ① 내 글 수정 ② 본문 수정 ③ 수정한 글 게시하기 | **‘고치기만 하면 친구들에게는 예전 글이 보여요.’** 같은 글과 댓글이 이어지는 결과를 보여 줌 |

학생 편 전체에서 같은 가상 학생·같은 원고를 사용한다. 예: 김하늘의 ‘작은 우산이 준 큰 마음’. 처음 쓴 문장이 피드백 뒤 어떻게 달라지고, 그 문장이 게시판에 어떻게 나타나는지 연속해서 보여 준다.

## 5. 교사 편 — 페이지 순서와 캡처 설계

교사 편의 기본 촬영 시나리오는 **‘학생용 태블릿 중 한 대를 골라 수업을 열고, 교사 PC를 연결해 지도’**로 잡는다. 학생용 태블릿을 사용하는 준비 단계를 첫 장의 제목과 핵심 문구에 명시한다. 이 태블릿은 학생들이 사용하는 와이파이에 연결하고, 충전기를 연결한 채 수업 종료까지 도토 화면을 켜 둔다. ‘교사가 사용하는 아무 기기에서 먼저 방을 연다’는 식으로 안내하지 않는다. 별도 PC를 사용하지 않는 경우에는 수업을 연 학생용 태블릿의 교사 화면에서 지도할 수 있다.

| 페이지·제목 | 캡처할 상태 | 화살표·번호로 짚을 곳 | 한 줄 설명·완료 모습 |
| --- | --- | --- | --- |
| **T01 학생용 태블릿 한 대로 수업을 열어요** | 학생용 태블릿에서 dotoschool.uk 접속 → 시작 화면의 수업 열기 → 수업 이름 입력 화면 | ① 수업 열기 ② 수업 이름 ③ 방 열고 코드 받기 | 준비: ‘학생용 태블릿 중 한 대를 사용하세요.’ 학생 와이파이·충전·화면 유지 아이콘. 핵심: ‘이 태블릿의 도토 화면을 수업이 끝날 때까지 켜 두세요.’ 완료: 코드가 발급된 서버 관리 화면 일부 |
| **T02 PC에서도 지도해요** | 서버 관리의 교사용 코드 부분 → PC의 통합 입장 화면 | ① 8자리 교사용 코드 ② PC에서 코드 입력 ③ 방 입장하기 | 교사용 코드와 학생용 코드의 전달 대상을 기기 그림으로 연결. 교사 입장에는 학생 이름을 입력하지 않음. 태블릿의 어둡게 켜 두기는 잠금 기능이 아님을 짧게 안내 |
| **T03 글쓰기 주제를 준비해요** | 게시판 → 그룹 만들기/그룹 설정 창 | ① 그룹 만들기 ② 그룹 이름·글쓰기 안내 ③ 저장하기 | 완료: 게시판에 생긴 주제 칸. 추가자료·생각 질문·출처 칸 설정은 A01 연결. 수업 이름, 게시판 제목, 그룹 제목은 실제 캡처 안에서 짧게 구분 |
| **T04 학생을 초대해요** | 학생용 입장 코드·QR 창 → 참여 학생 명단 | ① 학생용 6자리 코드/QR ② 학생 입장 ③ 명단 확인 | 학생에게는 학생용 코드·QR을 보여 줌. ‘아직 글이 없어도 입장했을 수 있어요.’ 참여 명단과 현재 연결 상태를 함께 확인 |
| **T05 쓰는 중인 글을 살펴요** | 초안·게시글·원고 없음 상태가 섞인 전체 글 화면 | ① 전체 글 ② 원고 없음/초안 등 상태 필터 ③ 학생 글 크게 보기 | ‘게시하기 전 글도 확인할 수 있어요.’ 한 학생이 여러 원고를 가질 수 있으므로 원고 수를 학생 수로 읽지 않도록 표시 |
| **T06 문장에 피드백을 남겨요** | 원고 상세에서 구절 선택 → 피드백 입력 창 → 노란 표시 | ① 문장 드래그 ② 피드백 하기 ③ 내용 작성·보내기 | 큰 캡처는 구절 피드백에 집중. 글 전체 피드백 입력 칸은 보조 확대 상자. 완료: 학생 S03 화면과 같은 구절·같은 피드백 |
| **T07 도움 요청과 질문에 답해요** | 도움 요청 알림/필터와 새 메시지 필터 → 원고 상세 대화 | 도움: 요청한 글 보기 → 도움 제공 → 요청 확인 완료. 메시지: 새 메시지 → 대화 → 답장 | 두 경로를 작은 두 패널로 구분. 한 패널마다 화살표 2~3개. ‘나중에 보기’는 알림창만 닫고 요청은 남는다는 점을 짧게 안내 |
| **T08 고친 글을 다시 확인해요** | 고친 글 확인 필터 → 수정된 원고·피드백 카드 | ① 고친 글 확인 ② 바뀐 본문 읽기 ③ 확인 완료 | 더 고칠 부분이 있으면 다시 살펴봐요. 교사의 확인은 게시 허가 버튼이 아님. 직접 수정은 별도 A03 페이지로 연결 |
| **T09 완성 글을 함께 읽어요** | 게시판과 열린 글/댓글 영역 | ① 게시판 ② 글 펼치기/읽기 ③ 댓글 작성 허용 | ‘함께 읽을 때는 게시판 화면을 보여 주세요.’ 수업 제안: 인상 깊은 문장을 골라 댓글로 이유 나누기. 개별 피드백과 대화는 교사 화면에 보일 수 있으므로 교실 제시용 캡처는 공개 내용 중심으로 준비 |
| **T10 수업을 마치고 결과를 간직해요** | 수업을 연 기기의 종료 확인 → 지난 수업의 해당 수업 카드 | ① 수업 마치기 ② 종료 확인 ③ 결과 내보내기 | 종료 후 지난 수업으로 이동한 모습을 표시. 나중에는 시작 화면의 지난 수업에서 찾을 수 있음. 완료: 내려받은 HTML을 열어 읽는 작은 화면. ‘PC 연결 나가기’와 수업 종료를 나란히 비교 |
| **T11 다음 시간에 이어서 열어요** | 같은 브라우저의 지난 수업 → 재개된 수업의 새 입장 코드 | ① 지난 수업 ② 다시 수업 열기 ③ 새 코드 안내 | ‘지난 원고를 이어가며 새 입장 코드를 안내해요.’ 수업 보기(보관 내용 열람)와 다시 수업 열기(학생 연결 재개)를 구분 |

## 6. 필요한 상황에서 찾아보는 부록

부록은 기본 흐름 중간에 긴 설명으로 끼워 넣지 않는다. 해당 화면 아래에 ‘자료를 넣으려면 A01’처럼 작은 연결 표시를 둔다. 최종 장수는 캡처 크기를 보며 나눈다.

| 항목 | 담을 내용 | 화면 구성 |
| --- | --- | --- |
| **A01 자료를 주고 출처를 적기** | 교사: 그룹 설정 → 수업 자료·글쓰기 도움 → 질문·자료·출처 칸 설정. 학생: 수업 도움 보기와 출처 적기 | 교사 설정 / 학생에게 보이는 결과를 연결한 두 장 권장. 서평 예시·조사 예시는 흐린 입력 안내이며 질문이 자동 저장되는 기능은 아님 |
| **A02 글과 그룹 정리·복원** | 교사의 그룹 이동, 글·그룹 순서 변경, 그룹 삭제와 휴지통 복원 | 이동 전후 한 쌍. 삭제·복원은 별도 한 장. 삭제 그룹의 원고·게시글·피드백·댓글이 함께 이동하고 30일 동안 복원 가능함을 짧게 표시 |
| **A03 교사가 직접 수정하기** | 원고 상세 → 직접 수정 → 본문 편집 | 교사 스위치와 학생에게 반영된 문장을 연결. 학생이 스스로 고쳐 쓰는 피드백 절차를 먼저 익힌 뒤 소개 |
| **A04 화면을 보기 좋게 바꾸기** | 학생: 더 보기 → 줄간격 등 필요한 서식. 교사: 카드 크기, 나란히 보기, 게시글 자동으로 펼치기 | 버튼 사전 형태의 작은 확대 캡처. 서로 다른 기능을 하나의 연속 절차처럼 화살표로 연결하지 않음 |
| **A05 연결이 끊겼을 때** | 연결 안내 확인 → 수업을 연 기기의 도토 화면·네트워크 확인 → 다시 연결 | 오류 화면 → 조치 → 연결된 상태. 같은 와이파이만으로 모든 학교망에서 연결이 보장된다고 쓰지 않음 |
| **A06 글이 안 보이거나 게시가 안 될 때** | 아래 상황별 구분 사용 | 증상 한 줄 + 실제 상태 캡처 + 할 일 한 줄. 필요하면 두 장으로 분리 |

A06의 상황별 문구:

- **쓰던 글이 안 보여요:** 먼저 같은 기기·브라우저·주소인지 확인 → 내가 쓰던 글. 공용 기기의 사용자가 바뀐 경우에만 다른 이름으로 새로 입장.
- **게시하기를 누를 수 없어요:** 제목·본문이 있는지 확인 → 연결·저장 상태 확인. ‘게시한 글과 같아요’는 새 변경이 없는 상태.
- **고친 글이 친구에게 안 보여요:** 수정한 글 게시하기.
- **댓글을 쓸 수 없어요:** 댓글 작성 허용 상태를 선생님에게 확인.
- **잘못 게시했어요:** 자기 글 열기 → 게시 내리기. 원고와 피드백은 남음. 댓글 삭제는 자기 댓글에서 사용하며, 교사는 모든 댓글을 삭제할 수 있음.
- **저장하지 못했어요:** 원고를 닫거나 브라우저 데이터를 지우기 전에 내용을 별도로 복사해 두고 교사에게 알리기. 자동 저장이 성공했다고 안내하지 않기.

## 7. 캡처와 화살표 편집 규칙

### 한 장의 기본 틀

```text
S03  선생님 말을 읽고 고쳐요                  쓰기 > 고치기 > 게시

┌──────────────────────────────────────────────┐
│                                              │
│               실제 화면 캡처                 │
│                                              │
│   ① 노란 구절을 눌러요 ───────→ [구절]       │
│                                              │
│   ② 본문을 고쳐요 ───────────→ [본문]       │
│                                              │
│   ③ 고쳤어요를 눌러요 ───────→ [버튼]       │
│                                              │
└──────────────────────────────────────────────┘

✓ 고친 뒤 선생님께 확인을 요청했어요.       이미 게시한 글은 S08
```

- 화면 캡처가 페이지의 약 75~85%를 차지하게 한다.
- 제목은 ‘피드백 기능’보다 ‘선생님 말을 읽고 고쳐요’처럼 행동으로 쓴다.
- 한 장에 기본 캡처 1개, 필요할 때 결과 캡처 1개. 세 화면이 꼭 필요하면 작은 순서도 또는 다음 장으로 나눈다.
- 화살표는 보통 2~3개. 번호와 짧은 동사를 함께 붙인다. 버튼 위를 가리지 않는다.
- 클릭할 곳은 번호 화살표, 확인할 상태는 테두리 확대, 드래그는 시작·끝이 보이는 이동 화살표로 구분한다.
- 조작 뒤 바뀐 화면이나 완료 표시를 꼭 보여 준다. 버튼 위치만으로 장을 끝내지 않는다.
- 추가 설명은 ‘게시하면 친구들도 읽어요’처럼 한 문장만 둔다. 한 장에 많은 설명이 필요하면 목표를 나눈다.
- 기능을 처음 소개할 때는 화면 전체로 위치를 알려 주고, 다음부터는 관련 영역을 크게 잘라 쓴다.
- 학생은 태블릿 화면과 ‘누르기’, 교사는 PC 화면과 ‘클릭·드래그’를 기본으로 한다. 실제 태블릿 키보드로 가려지는 위치는 촬영 때 별도 확인한다.
- 역할 구분색은 학생 초록 / 교사 갈색 정도로 제한하되, 색 외에 ‘학생·교사’ 글자도 표시한다.
- QR·입장 코드 화면은 안내서 촬영 전용 수업으로 준비한다. 예시 코드임을 표시하고 실제 수업의 교사용 코드는 배포 자료에 남기지 않는다.

### 특히 화면으로 구별해야 할 개념

| 혼동하기 쉬운 것 | 보여 줄 방식 |
| --- | --- |
| 저장 / 게시 | ‘이 기기에 저장됨’과 ‘게시하기’를 서로 다른 확대 상자로 표시 |
| 쓰던 원고 / 게시판의 완성본 | 같은 원고의 수정 전후 문장을 두 화면에서 비교 |
| 교사용 코드 / 학생용 코드 | 교사용 8자리 → 교사 PC, 학생용 6자리 → 학생 태블릿 그림 |
| 수업을 연 기기 / 지도용 PC | 수업 유지 기기에 ‘끝까지 켜 두기’, PC에는 ‘지도하기’ 표시 |
| 읽었어요 / 고쳤어요 / 확인 완료 | 학생 읽기 → 학생 수정 응답 → 교사 확인 순서의 상태 띠 |
| 도움 요청 / 메시지 / 피드백 / 댓글 | ‘도와주세요 / 질문과 답장 / 글에 대한 의견 / 친구와 나누는 말’로 사용 장면 구별 |
| 게시판 / 전체 글 | 같은 수업을 두 화면으로 비교해 공개된 글과 미게시 원고가 어디에 보이는지 표시 |
| PC 연결 나가기 / 수업 마치기 | PC만 나감 / 전체 수업 연결 종료의 결과를 함께 표시 |
| 수업 보기 / 다시 수업 열기 | 보관 내용 열람 / 새 코드로 수업 재개라는 결과로 구분 |

## 8. 촬영 준비와 제작 순서

1. **가상 수업 하나를 정한다.** 같은 주제·학생·원고를 유지한다. 학생 3~4명으로 원고 없음, 미게시 초안, 피드백 후 수정, 게시 완료 상태를 준비한다.
2. **현재 실제 수업 모드에서 장면을 재현한다.** 시안·가상 수업 화면은 구도 확인에 활용하되, 최종 안내서 캡처는 실제 수업 화면에서 촬영한다. 역할 전환 메뉴와 ‘UI 시안’ 안내가 사용자 기능으로 섞이지 않게 한다.
3. **한 학생의 전체 과정을 먼저 촬영한다.** S01 → S02 → 교사 T06 → 학생 S03 → 교사 T08 → 학생 S04 → 다른 학생 S05. 같은 문장과 피드백을 유지해 두 역할의 연결이 보이게 한다.
4. **수업 준비·마무리와 분기 장면을 촬영한다.** 이어 쓰기, 도움 요청, 재게시, 지난 수업, 연결 문제를 보완한다.
5. **S03과 T06 두 장을 먼저 편집한다.** 글자 크기·캡처 비율·화살표 모양을 정한 뒤 나머지 장에 같은 규칙을 적용한다.
6. **화면과 안내를 대조한다.** 화살표가 가리키는 버튼을 누르면 다음 캡처 상태가 되는지, 보조 기능이 필수 단계처럼 보이지 않는지 확인한다.
7. **학생용 한 장 요약을 파생한다.** ‘입장 → + → 쓰기 → 피드백 → 게시 → 댓글’의 작은 캡처를 이어 붙여 교실 게시용으로 사용한다. 상세 안내서는 페이지 번호로 찾아간다.

## 9. 현재 확인 근거와 제작 시 확인할 범위

현재 README와 실제 구현을 대조하고, 로컬 실행 화면에서 시작·통합 입장·수업 생성 입력 화면을 확인했다. 가상 수업 모드에서는 학생 게시판·새 원고·교사 전체 글의 화면 배치를 확인했다. 이번 작업은 구성 설계이며 완성 안내서 촬영이나 실제 다기기 수업 검증을 수행한 것은 아니다.

최종 촬영 전에는 실제 수업 모드에서 교사 PC 연결, 구절 피드백, 학생 수정·게시·댓글, 종료·내보내기·재개를 이어서 확인한다. 태블릿 화면 배치와 키보드가 켜진 상태도 대상 기기에서 확인한다. 예전 시안에는 ‘수업 종료’처럼 현재 실제 화면의 ‘수업 마치기’와 다른 문구가 있으므로 최종 캡처의 버튼명으로 통일한다.

주요 대조 파일:
