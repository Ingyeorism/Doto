# 도토 UI 1.3 — 선택한 피드백 적용 기록

2026-09-05 · 교사 PC / 초등학생 태블릿 화면 키보드 · 모두 프로그램 사용 초보

## 선택 확인

사이드 브라우저의 ‘도토 피드백 선택표’에서 체크된 **f1, f2, f4, f5, f6, f7, f8, f9, f10, f11, f12 — 11개**를 직접 읽었다. f3와 하단 개발 우선순위 p1–p8은 체크되지 않았다. 하단에 중복된 문구가 있어도 위에서 선택한 사용성 요구는 적용하며, 별도의 실제 통신 구현·실기기 검증·학생 이미지 업로드 작업으로 확대하지 않았다.

## 적용 판단

| 선택 요구               | 구현                                                                | 이렇게 정한 이유                                                               |
| ----------------------- | ------------------------------------------------------------------- | ------------------------------------------------------------------------------ |
| 원고 없는 학생도 확인   | 참가자 모델과 원고를 분리. 참여 인원·명단·원고 개수, 원고 없음 필터 | 참가자는 글을 쓰기 전에도 존재함. 원고 삭제를 학생 퇴장으로 처리하지 않음      |
| 도움이 필요한 학생 찾기 | 초안·게시됨·도움 요청·고친 글 확인 필터                             | 교사가 수업 중 바로 써야 하는 동작이라 설정창에 숨기지 않음                    |
| 자료 링크               | 그룹 설정의 접힌 ‘수업 자료·글쓰기 도움’에 최대 2개                 | 별도 자료 관리 화면 없이 해당 주제에서 준비. 링크는 새 탭으로 열어 원고 유지   |
| 수정본 공개 구분        | 저장 상태와 공개 상태를 따로 표시, ‘고친 글 올리기’                 | 저장과 공개를 아이가 같은 동작으로 오해하지 않도록 기본 표시                   |
| 저장 확신               | 저장 중·저장됨·저장 실패를 실제 저장 결과에 맞춤                    | 가짜 타이머로 저장 성공을 표시하지 않음                                        |
| 잘못 고른 그룹          | 원고 위에 그룹 이름. 도움 요청 안에서 이동 요청                     | 학생 화면의 관리 기능을 늘리지 않고, 교사가 소속 변경을 처리                   |
| 피드백 반영 확인        | 읽었어요 / 고쳤어요 → 교사 확인 완료 또는 다시 살펴봐요             | 자동 채점이나 제출 강제가 아닌 대화 상태. 상세 변경 이력은 추가하지 않음       |
| 키보드와 주요 동작      | 하단 동작 막대가 화면의 실제 표시 영역을 따름                       | 본문을 쓰다가 맨 위로 돌아가 게시 버튼을 찾는 부담을 줄임                      |
| 첫 문장 시작            | 교사가 질문 최대 3개를 선택 입력. 서평·조사 질문 예시               | 정답 자동 생성·필수 문장 틀보다 학생의 생각을 돕는 정도로 제한                 |
| 출처 작성               | 그룹별 출처 칸 표시 옵션. 기관·자료명·날짜·선택 주소                | 서평 등 모든 수업에 칸을 강제하지 않음. 켠 뒤에도 공란·부분 입력으로 게시 가능 |
| 그림 자료               | 교사가 링크와 함께 또는 그림만 제공. 크기 자동 축소                 | 학생 업로드·파일 관리를 늘리지 않고 읽기 자료부터 제공                         |

학생의 글쓰기 화면에서는 자료와 질문을 ‘수업 도움 보기’ 안에 접어 둔다. 처음 화면을 안내 문장으로 채워 본문이 보이지 않는 문제를 줄였다. 게시판의 그룹에는 자료 링크가 바로 보인다. 제목과 본문 외에 도움 요청 설명·출처·생각 질문 답변을 필수로 요구하지 않는다. 이동 요청만 옮길 그룹을 골라야 한다.

## 저장과 표시 규칙

- 새 데이터도 기존 게시판 저장 레코드에 함께 보관한다. 예전 저장 데이터에 참가자 정보가 없으면 기존 원고의 소유자로 명단을 보완하며 글·피드백을 초기화하지 않는다.
- 참가자·도움 요청은 개인 원고와 별도로 유지한다. 현재 명단은 UI 시안 데이터이며 실제 태블릿 연결 상태를 증명하지 않는다.
- 출처 변경은 공개본 비교에 포함한다. 빈 출처 행이나 피드백 위치 변경만으로 재게시를 요구하지 않는다.
- 빈 질문·빈 자료는 저장할 때 제외한다. 자료 이름만 생략하면 기본 이름을 쓴다. 위험한 실행 주소는 자료 링크로 만들지 않는다.
- 출처의 완전히 빈 행은 공개 목록에서 제외한다. 일부만 적은 출처는 그대로 표시하며, 잘못 쓴 주소를 실행 링크로 만들지 않는다.
- 교사 그림은 원본 20MB 이하 PNG·JPG·WebP를 받아 긴 변 최대 1280px로 줄여 보관한다. 원본 첨부·다운로드 보관함은 아니다. 저장 공간 부족은 기존 저장 실패 안내를 따른다.
- 피드백 상태는 공개 글에 들어가지 않는다. ‘고쳤어요’는 학생의 자기 확인이며 교사의 확인과 구별한다. 문장이 바뀌어도 메시지를 보관한다.

| 도움 요청             | 설명 없이 요청 → 교사 도움 요청 필터 1개 → 확인 완료                                                      |
| 그룹 이동 요청        | 학생이 요청한 그룹으로 교사가 이동. 원고·게시본의 그룹과 출처 유지, 요청 해제                             |
| 피드백 확인           | 학생 고쳤어요 → 교사 고친 글 확인 → 확인 완료. 새로고침 후 상태 유지                                      |
| 좁은 편집 영역        | 800×520에서 가로 넘침 없음. 본문 커서가 끝에 있을 때 하단 막대 y=449–520, 게시 버튼 화면 안에 유지        |

검사는 기존 게시판과 분리된 `?simulation=ui13-check` 공간에서 했다. 실제 Android 화면 키보드·한글 조합·길게 누르기·PC와 태블릿의 동시 연결 검증은 아니다. 모사한 화면 크기는 확인 후 해제했다. 가상 수업 보고서 1.2는 당시 관찰 기록으로 남기고, 이번 수정 내용을 소급해 바꾸지 않는다.

표시 영역 처리는 [MDN VisualViewport 설명](https://developer.mozilla.org/en-US/docs/Web/API/VisualViewport)을 참고했다. 기기별 키보드 동작은 실제 기기에서 별도로 확인해야 한다.

## 사용 위치

- 교사: **전체 글 → 상태 필터 / 참여 학생 명단**
- 교사: **게시판 → 그룹 설정 → 수업 자료·글쓰기 도움**
- 학생: **게시판의 그룹 + → 글쓰기 하단의 도움 요청·글 올리기**
- 학생: **수업 도움 보기 / 출처 남기기 / 피드백의 고쳤어요**

새 기능을 사용하기 위해 전체 설정창에서 여러 스위치를 켤 필요는 없다. 수업에 따라 노출 자체를 달리할 필요가 있는 출처 칸만 그룹별 표시 옵션으로 둔다.
