# 도토 첫 실제 수업 버전 구현 기록

2026-09-05. 기획서 1.3과 프로젝트의 ‘교실 글쓰기 앱 검토’, ‘검토 교실 글쓰기 기획’, ‘도토 UI 시안 생성’ 대화를 검토했다. 읽기 도구가 일부 긴 대화를 불러오지 못한 부분은 해당 프로젝트 대화 로그의 사용자 메시지로 확인했다.

## 사용자 의도와 기존 상태

핵심은 학생의 실제 본문을 반 전체에서 보며 즉시 도와주는 경험, 초등학생의 한국어 글쓰기, 교사와 운영자의 간단한 실행이다. 직접 수정과 게시·댓글을 첫 버전에 포함하고, 학생은 그룹의 +에서 새 원고를 만든다. 기존의 따뜻한 UI와 선택한 11개 피드백을 유지했다.

시작 시점에는 React/Tiptap 화면, 그룹 게시판, 편집과 구절 피드백, 도움 요청, 출처와 수업 자료, 로컬 시안 저장·휴지통이 있었다. 실제 수업 생성·기기 연결·인증·협업·지난 수업·내보내기는 예시 화면이었다.

## 구현한 내용

| 기획 범위 | 실제 구현 |
|---|---|
| 수업 시작 | 기본 그룹 하나와 빈 수업, 임의 6자리 코드, 스캔 가능한 QR·초대 링크 |
| 입장·권한 | 교사 권한 토큰, 학생 재입장 토큰, 동명이인 구분, 새 입장 잠금·기존 학생 복귀 |
| 실제 글 보기 | 학생당 교사 연결 하나, 원고별 Y.Doc, 본문 변경분 동기화, 교사 카드 전체 본문 |
| 협업 편집 | Tiptap Collaboration, 개인 실행 취소, 직접 수정·구절 피드백 |
| 피드백 위치 | Yjs 상대 위치, 경계 밖 이어쓰기 제외, 삭제·교체·실행 취소·다시 실행 |
| 알림 | 관찰·새 피드백·수정 중 표시 설정, 교사 커서 표시, 기본 설정 기억 |
| 게시·댓글 | 교사가 소유권을 확인해 공개본 확정, 수정본 재게시·댓글 유지, 게시 내리기·댓글 삭제 |
| 그룹·수업 도움 | 기존 그룹·정렬·이동·자료·질문·출처·도움 요청·피드백 확인 상태를 실제 수업에 연결 |
| 휴지통 | 교사 저장소에서 30일 보관, 그룹·원고별 복원, 연결된 학생에 반영 |
| 저장·재접속 | IndexedDB에 수업·원고별 CRDT 상태 보관, 실제 저장 결과 표시, 직접 연결 복귀 시 양쪽 변경 합치기 |
| 지난 수업 | 실제 저장 목록, 수업 읽기, 종료한 수업을 새 코드로 다시 열기 |
| 내보내기 | 교사용 HTML 한 파일: 현재 원고·피드백·공개본·댓글·출처·휴지통 글 |
| 실행·배포 준비 | Windows 더블클릭 실행/종료, Node 단일 앱 서버, Docker Compose와 Caddy HTTPS 설정 예시 |

학생에게는 자기 원고와 피드백만 보내며 공개 게시글은 별도 복사본이다. 중앙 WebSocket은 방·참가자·SDP/ICE 연결 신호만 처리한다. TURN, 터널, 문서 WebSocket 중계, 중앙 문서 DB, 가입·결제·AI 채점은 추가하지 않았다.

기존 시안은 `src/PreviewApp.tsx`와 `?preview=1`로 보존했다. 이전 localStorage 시안 자료와 가상 수업은 실제 IndexedDB 수업 목록과 별도다. 시안 자료를 실제 학생 자료로 자동 이전하지 않는다.

## 실제 확인

- Windows, Node.js 22.22.2, 설치된 Chrome. 같은 PC의 **분리된 브라우저 컨텍스트**에서 교사 1명·학생 2명으로 검증했다.
- 타입 검사와 배포 빌드 통과.
- `scripts/classroom.spec.ts`: 입장·두 원고의 실시간 표시·교사 직접 수정·전체 메시지·정확한 구절 피드백·경계 앞 이어쓰기·전체 교체·실행 취소/다시 실행·연결 단절 중 양쪽 독립 수정 후 합치기·게시·댓글·학생/교사 새로고침·학생 저장소의 원고/피드백 분리·종료·HTML 파일 내용·새 코드 재입장 확인.
- 같은 검사에서 중앙 WebSocket 송수신을 관찰해 작성한 본문과 피드백이 포함되지 않았음을 확인했다.
- `scripts/smoke-signaling.mjs`: 학생의 교사 전용 요청 거부, 문서 메시지 거부, 동명이인 독립 ID, 신규 입장 잠금, 기존 학생 재입장, 교사 복귀와 새 코드 확인.
- 기존 휴지통 검사 4개와 수업 도움/출처/공개본 검사 3개 통과.
- Docker Compose 설정 해석 검사 통과. 실제 외부 서버에 배포하거나 인증서를 발급한 결과는 아니다.
- `도토 열기`의 실제 서버 실행과 `도토 서버 종료`의 해당 프로세스 종료, 다시 실행까지 이 PC에서 확인했다. 현재 앱은 `http://localhost:3000/teacher/start`에서 실행 중이다.

첫 글자의 상대 위치를 라이브러리가 문서 시작으로 잘못 분류하는 문제, 협업 에디터 재생성 때 절대 위치를 다시 매핑하는 문제, 재접속 시 양쪽 상태 벡터를 모두 교환하지 않는 문제를 실제 검사에서 찾아 수정했다. Yjs 실행 취소에서 새로 만들어지는 항목의 위치는 메시지와 분리해 교사에게 반영하며 학생의 오프라인 위치 복원 정보도 보관한다.

## 아직 확인할 것

- 실제 Android 한글 조합 입력, 화면 키보드의 커서 가림, 실제 터치 길게 누르기.
- 교사망과 학생망이 다른 학교의 WebRTC 직접 연결.
- 실제 N100의 OS·도메인·접속 정보에 맞춘 배포·HTTPS·자동 실행.
- 실제 한 반 규모의 수업 성능. 같은 PC의 3개 브라우저 검사로 N100 수백 명 성능을 보장하지 않는다.

PDF와 펜 필기는 기획서 12절의 다음 단계다. 이번 첫 버전 구현 완료 범위에 섞지 않았다. 저장소는 사용하는 브라우저·주소에 귀속되며 중앙 백업이 없으므로 필요한 수업은 HTML로 내보낸다.
