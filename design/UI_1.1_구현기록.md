# UI 1.1 구현 기록 — 2026-09-05

사용자 요청: 주제 그룹을 첫 버전에 포함하고 학생/교사 경로를 분리한다. 교사가 드래그한 정확한 구절에 피드백을 남기며 학생은 호버 또는 길게 누르기로 읽는다. 원고 수정·삭제 시의 정책을 정하고 기획서도 수정한다. 이번에는 구현만 하며 테스트는 나중에 모아서 한다.

반영한 코드:

- 역할별 URL과 학생 게시판 중심 이동. 그룹 +로 독립된 원고 생성, 비공개 원고 이어쓰기, 교사 안내 글 작성.
- 그룹 생성·이름/안내 수정, 드래그와 버튼으로 순서 변경, 빈 그룹 삭제 제한.
- 게시글 정렬 다섯 가지, 직접 배치, 그룹 간 드래그와 선택 메뉴 이동. 원고·게시본 소속을 함께 변경하고 피드백·댓글 ID 유지.
- 실제 Tiptap 선택 범위에 ‘피드백 하기’ 메뉴와 인용문 입력창. 일반 피드백은 별도로 유지.
- 본문과 별도로 보관하는 피드백 앵커. 경계 확장 방지, 내부 수정 매핑, 삭제된 구절의 메시지 보존, 중첩 피드백 표시.
- 데스크톱 호버, 500ms 터치/펜 길게 누르기, 클릭과 키보드 접근, 바깥 클릭·스크롤·Escape 닫기.
- 현재 에디터의 최근 문서 이력으로 실행 취소/다시 실행 때 범위 복원. 문자열 일치만으로 재부착하지 않음.
- 한국어 기획서 1.1, README, 실행 스크립트의 기본 URL 수정.

판단 근거: 패들릿 공식 섹션·정렬 안내를 읽고 도토에 필요한 그룹, 그룹별 +, 수동/자동 정렬, 이동을 채택했다. 글이 있는 그룹의 일괄 삭제 대신 빈 그룹만 삭제하도록 결정했다. 출처와 세부 규칙은 기획서 4~7절에 기록했다.

## 이번에 실행하지 않은 것

사용자 요청에 따라 빌드, 타입 검사, 린트, 자동 테스트, 브라우저 실행·화면 조작 검증, Android 실기기 검증을 하지 않았다. 이 문서는 구현 기록이며 검증 완료 기록이 아니다. `UI_완료기록.md`는 이전 1.0 시안에 대한 기록이다.

후속 확인은 기획서 13절에 모았다. 특히 한글 입력 중 범위 매핑, 전체 교체/삭제 후 Undo/Redo, 반복·겹치는 구절, 모바일 길게 누르기와 스크롤, 그룹 이동 후 공개본·개인 원고·댓글 일관성, 역할별 화면을 확인한다.

## 현재 범위

프런트엔드 단일 탭 UI 프로토타입. 새로고침하면 초기화되며 다른 탭/기기와 동기화하지 않는다. URL과 메뉴 분리는 실제 인증이 아니다. 실제 연결·문서 권한·Yjs·영구 저장은 기존 기획의 후속 구현 대상이다. 범위 복원용 최근 이력은 메모리에 제한하여 보관하며 편집기를 닫으면 초기화된다.
