# 태블릿 호스트 실제 연결

2026-09-08. 승인한 태블릿 서버 UI를 기존 실제 수업에 연결했다. `?preview=tablet`의 예시 수업과 실제 수업은 계속 분리한다.

## 실행과 사용

`도토 열기.cmd` 또는 `npm run dev`로 실행하고 `http://localhost:3000/teacher/start`를 연다. 실제 수업 주소에는 `preview`를 붙이지 않는다. 여러 기기에서는 기존에 운영하는 도토 HTTPS 주소를 공통으로 사용한다. 로컬 확인용 `localhost`는 다른 기기에서 접속할 주소가 아니다.

1. 학생망에 연결한 태블릿에서 **수업 열기 → 수업 이름 → 방 열고 코드 받기**를 선택한다. PC에서 직접 수업을 여는 기존 사용도 가능하다.
2. 서버 관리 화면에 교사용 8자리 코드와 학생용 6자리 코드가 모두 표시된다.
3. 교사 PC는 같은 **방 입장하기**에 교사용 코드를 입력한다. 학생은 학생용 코드와 이름을 입력한다. 역할은 서버가 코드와 재입장 토큰으로 판단한다.
4. 태블릿과 교사 PC에서 같은 **전체 글 · 게시판** 화면으로 편집·피드백·질문과 자료·그룹·댓글·휴지통을 다룬다.
5. 태블릿의 **어둡게 켜 두기**로 도토 화면을 어둡게 유지할 수 있다. 교사 PC의 **PC 연결 나가기**는 해당 PC 연결만 종료한다.
6. 수업을 연 기기의 **수업 마치기**로 전체 수업을 마치고 보관한다.

## 통신과 권한

- Node 서버는 웹 화면, 코드 발급·역할 확인·입장 잠금·재입장, WebRTC 연결 신호를 담당한다. 원고·개인 피드백·메시지를 중앙 서버로 중계하지 않는다.
- 수업을 연 브라우저가 호스트다. 학생과 원격 교사 PC는 각각 호스트와 DataChannel을 연결한다. 태블릿에서 HTTP 서버를 실행하거나 새 앱을 설치하는 방식이 아니다.
- 호스트만 중앙 서버에서 수업 생성·종료·교사 코드 변경을 할 수 있다. PC에서 바꾼 수업 설정은 호스트가 인증된 DataChannel 요청으로 받아 반영한다.
- 호스트 ID는 -1, 원격 교사는 -1보다 작은 별도 ID, 학생은 양수 ID다. 클라이언트가 요청에 적은 역할이나 작성자 ID를 신뢰하지 않는다. 교사 작성 글은 공통 선생님 작성자(-1)를 사용해 태블릿과 PC가 같은 교사 초안을 편집한다.
- 원격 교사는 전체 원고와 개인 피드백을 받지만 호스트·학생·다른 교사 기기의 재입장 토큰은 받지 않는다. 학생에게는 자기 초안·개인 피드백과 반에 게시한 완성본만 전달한다.
- 학생용 QR에는 학생 코드만 담는다. 새 학생 입장을 잠가도 등록된 학생의 재입장과 교사 코드 입장은 가능하다.
- 교사 코드 변경은 이전 코드로 새로 입장하는 것을 막는다. 이미 연결된 교사 PC와 저장한 기기 토큰은 유지한다. 교사 기기별 강제 퇴장·권한 취소 기능은 추가하지 않았다.
- 중앙 서버의 입장·코드 확인·방 생성 요청에는 연결별 1분 40회 제한이 있다. 이 제한은 계정 인증이나 네트워크 단위 공격 방어를 대신하는 장치는 아니다.

## 저장과 복원

- 호스트의 전체 수업은 기존 IndexedDB 보관 키에 저장한다. 원격 교사는 `doto.lesson.controller.<수업 ID>.<기기 ID>`에 별도로 저장한다. 기존 교사 보관함과 충돌하지 않는다.
- 현재 탭은 세션 저장소의 자기 연결 정보를 먼저 사용한다. 학생이 다른 이름을 입력하면 이전 학생의 토큰을 재사용하지 않는다. 다른 탭의 학생 입장이 현재 탭의 새로고침 후 작성자를 바꾸지 않는다.
- 원격 교사가 명시적으로 나가면 자동 복원을 해제하고, 같은 수업에 다시 코드를 입력하면 기기의 기존 ID를 재사용한다.
- 호스트 새로고침 시 등록된 학생과 교사 PC의 연결을 다시 맺는다. 중앙 방이 유지되는 약 5분 안에는 기존 코드도 유지된다. 중앙 서버가 재시작됐거나 지난 수업을 다시 열면 호스트에 저장한 참가자 토큰을 복원하고 새 코드를 발급한다.
- 원고는 Yjs로 양방향 동기화한다. 태블릿·교사 PC·작성 학생의 본문 변경을 합치고, 게시·그룹·피드백 요청은 호스트에 저장한 뒤 성공을 응답한다.
- 브라우저 저장 실패와 연결 실패는 실제 상태로 표시한다. 수업 결과 HTML 내보내기는 기존 기능을 사용한다. 원격 PC의 자동 호스트 승계나 중앙 문서 백업은 없다.

## 화면 유지

`use-host-device.ts`는 실제 Screen Wake Lock을 요청한다. 허용, 해제, 미지원·거절 상태를 구분하고 화면으로 복귀하면 다시 요청한다. 수업 종료와 설정 해제 시 잠금을 반환한다. 배터리 API를 사용할 수 있을 때만 실제 잔량과 충전 상태를 표시한다.

어두운 화면은 화면 위의 어두운 대화상자이며 OS 잠금이나 절전 모드가 아니다. 브라우저가 숨겨지면 화면 잠금 요청이 해제될 수 있고, HTTPS 등 보안 컨텍스트가 필요하다. 수업 중에는 도토를 화면에 열어 두어야 한다. [W3C Screen Wake Lock 명세](https://www.w3.org/TR/screen-wake-lock/)

## 검증

- `npm run build`: 타입 검사와 배포 빌드 통과. 기존 단일 번들 크기 경고는 남아 있다.
- 기존 `classroom.spec.ts`와 `diagnostics.spec.ts`: localhost 및 일반 HTTP LAN 조건에서 총 10개 통과. 공동 편집·비공개 피드백·게시·댓글·재입장·수업 보관과 기존 진단 동작을 확인했다.
- 새 `tablet-host.spec.ts`: 두 조건에서 총 2개 통과. 독립 브라우저 저장소 4개로 호스트·교사 PC·학생 2명을 연결했다. 어두운 화면 중 원고 전달, 양쪽 교사 편집, 학생 개인 원고·피드백 격리, 학생의 교사 권한 위조 차단, 재입장 토큰 비공개, PC 퇴장 후 수업 유지, 새로고침 복원, 같은 교사 ID 재사용, 올바른 작성자로 게시, 수업 종료·보관을 확인했다. 중앙 신호에 원고·피드백 본문이 포함되지 않는지도 검사했다.
- `node scripts/smoke-tablet-host.mjs`: 실제 WebSocket 서버에서 코드별 역할·입장 잠금·권한 위조 거절·코드 변경·재접속·호스트 복원·종료 검사 통과.
- `node --experimental-strip-types --test scripts/board-order.test.mjs`: 그룹 사이·같은 그룹·교사 초안의 위치 기반 이동, 정렬 전환, 저장 후 순서 유지 6개 통과.
- 인앱 브라우저의 별도 테스트 수업에서도 태블릿·PC·학생 둘의 실제 WebRTC 연결을 확인했다. 교사 PC와 태블릿에서 원고 수정, 개인 피드백, 게시, 그룹 이동, 교사 공통 초안을 확인했다. 다른 학생 탭 입장 후 이강우 탭을 새로고침해도 이강우의 원고와 작성자가 유지됐다.

HTTP LAN 자동 검사는 일반 HTTP 출처를 로컬로 매핑한 검사다. 실제 학교의 AP 격리·방화벽이나 물리적으로 다른 기기를 검증한 결과는 아니다. Android·iPad의 장시간 화면 유지·한글 입력·배터리, 실제 학교망 연결, 외부 서버 배포는 현장 검증이 남아 있다. 이번 작업에서 외부 운영 서버에 배포하지 않았다.

## 주요 파일

- `server/index.mjs`: 실제 코드·교사 기기 인증·신호 전달.
- `src/classroom.ts`: 호스트 권한·원격 교사·저장·문서 동기화.
- `src/App.tsx`, `src/RoomScreens.tsx`: 승인한 실제 입구·공통 교사 화면·서버 관리.
- `src/use-host-device.ts`: 화면 유지·배터리 상태.
- `scripts/tablet-host.spec.ts`, `scripts/smoke-tablet-host.mjs`: 새 연결 방식의 회귀 검사.
