# 도토 UI 1.2 구현 기록

2026-09-05 · Windows / Chromium 기반 Codex 인앱 브라우저

## 구현

- 글이 있는 그룹과 마지막 그룹을 확인 후 삭제하고, 관련 원고·게시본·피드백·댓글을 30일 휴지통에 보관한다. 그룹 전체와 개별 글을 복원할 수 있다.
- 게시판과 휴지통을 같은 localStorage 레코드로 저장하여 새로고침 후에도 유지한다.
- 그룹 +의 44×44 영역 중앙 정렬, 좌우 화살표 제거, 포인터 손잡이 드래그를 적용했다.
- 고정 소개와 드래그 안내를 없애고 교사가 편집하는 게시판 제목을 넣었다.
- 실제 삭제된 구간을 기준으로 피드백 범위를 처리하여, 구절 전체를 다른 문장으로 바꾸면 원래 인용문·메시지만 남긴다. Undo/Redo와 경계 이어쓰기도 확인했다.
- 일반 시안과 구분된 서평·국가유산 연습 공간을 추가했다. UI로 가상 원고 12개를 작성하고, 게시 8개·초안 4개·교사 피드백 2개·댓글 2개를 남겼다.

## 이번에 실행한 간단한 확인

| 확인                                                      | 결과                                                       |
| --------------------------------------------------------- | ---------------------------------------------------------- |
| `npm run build`                                           | TypeScript·Vite 통과. 번들 500kB 초과 안내만 남음          |
| `node --experimental-strip-types scripts/smoke-trash.mjs` | 데이터 검사 4개 통과                                       |
| 게시판 제목 저장·새로고침                                 | 유지                                                       |
| 그룹 삭제 취소→확인→새로고침→휴지통 전체 복원             | 원고 4개와 피드백 2개 포함 보관·복원                       |
| 그룹 및 게시글 손잡이 드래그                              | 그룹 순서 변경과 다른 그룹 이동 확인                       |
| 그룹 + 중심                                               | 44×44, SVG 중심 오차 0px                                   |
| 학생 호버 피드백 팝업                                     | 선택 구절의 메시지 표시                                    |
| 구절 전체 교체·Undo·Redo·경계 이어쓰기                    | 교체 시 표시 제거, Undo 복원, Redo 제거, 경계 추가 글 제외 |
| 가상 수업 작성·게시·피드백·수정·댓글                      | 두 수업의 순차 UI 흐름 완료                                |
| 800×520 편집 영역                                         | 가로 넘침 없음. 게시 버튼이 위로 벗어나는 사용성 문제 기록 |

처음 확인한 기존 HTML 드래그와 전체 구절 교체에는 문제가 있어 수정한 뒤 해당 흐름만 다시 확인했다. 예전 UI 1.1의 ‘검사 미실시’ 기록은 당시의 기록으로 유지한다.

## 해석 범위

한 브라우저에서 역할을 순차 전환했다. 실제 여러 학생의 수업·인터뷰·네트워크·성능 검증이 아니다. 실제 Android 화면 키보드·한글 조합·길게 누르기, 교사 PC와 태블릿 간 연결·인증·재접속은 확인하지 않았다. 브라우저의 작은 편집 영역은 키보드 공간을 모사한 배치 확인이다.

가상 수업의 지도약안·원고·예상 발언·개선 후보는 `reports/`에 함께 보관했다. 보고서 제안을 모두 구현한 것으로 취급하지 않는다.
