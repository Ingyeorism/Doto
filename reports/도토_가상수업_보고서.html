01 · 검토 보고서

도토 1차 UI·가상 수업 검토 보고서

2026-09-05 · 작성: AI 시뮬레이션 · 대상: 도토 사용이 서툰 초등학생과 교사

판단 요약

주제를 고르고 글을 쓰고, 선생님의 말을 읽어 고친 뒤 함께 읽는 기본 흐름은 UI 시안에서 이어졌다. 이번 요청의 그룹 삭제·휴지통·제목 편집·상단 정리도 반영했다. 다음 개선은 새 기능을 많이 늘리기보다 저장·게시 상태를 분명히 보여 주기, 태블릿 키보드가 열린 상태에서 쓰기 편하게 만들기, 교사가 도움이 필요한 학생을 찾기 쉽게 만들기에 집중하는 편이 좋다.

현재 시안은 실제 수업 운영을 검증한 제품이 아니다. 교사 PC와 학생 태블릿의 실제 연결, 참가자 인증, Android 한글 조합 입력과 화면 키보드는 아직 확인하지 않았다.

구분 이번에 한 일 해석 범위
코드 확인 TypeScript 포함 프로덕션 빌드, 휴지통 데이터 검사 4개 해당 코드 경로의 기본 오류·데이터 보존 확인
브라우저 조작 제목 변경, 삭제 취소·삭제·새로고침·복원, 그룹·글 드래그, 작성·게시·피드백·수정·댓글 Windows의 Chromium 기반 인앱 브라우저에서 확인한 UI 동작
작은 화면 800×520 CSS 픽셀의 편집 영역으로 변경하여 확인 화면 키보드가 공간을 차지한 상황의 배치 모사. 실제 Android 키보드가 아님
가상 수업 가상 교사 1명과 학생 6명의 역할을 번갈아 조작, 두 수업에서 원고 12개 생성 순차 역할 시뮬레이션. 6개 기기의 동시 접속·실제 아동 관찰이 아님
가상 피드백 각 인물의 예상 발언을 작성하고 실제 화면·기능과 대조 AI가 구성한 사용성 가설. 인터뷰·설문·현장 의견 수집 결과가 아님

학생 글은 자동화 도구로 입력했다. 이 입력 시간을 학생의 타자 속도나 수업 소요 시간으로 해석하지 않는다. 게시 8개·초안 4개는 상황을 다양하게 만들기 위해 의도한 조건이며 성공률 통계가 아니다.

2. 이번 UI 수정 결과

요청 반영 결과
글이 있는 그룹도 삭제 ‘정말 삭제하시겠습니까?’ 창에서 원고 수와 게시글 수를 보여 주고 확인 후 삭제
삭제 글의 임시 보관 그룹·미게시 원고·게시본·피드백·댓글을 30일간 휴지통에 보관. 그룹 전체 또는 글 하나씩 복원
새로고침 후 복원 활성 게시판과 휴지통을 이 브라우저에 함께 저장. 삭제한 그룹이 새로고침 때문에 다시 나타나지 않음
위쪽 + 정렬 기본 버튼 여백을 제거하고 44×44 클릭 영역 중앙에 배치. 측정한 중심 오차는 가로·세로 모두 0px
좌우 화살표 제거 그룹 이동 화살표 제거. 손잡이를 잡아 드래그하는 방식 유지
게시판 상단 간소화 기존 세 줄 소개와 손잡이 안내 문구 제거. 교사가 수정·저장·취소할 수 있는 게시판 제목으로 대체

삭제 확인의 ‘원고 4개 / 게시한 글 1개 포함’은 총 5개라는 뜻이 아니다. 게시본은 그 원고 중 게시한 글의 공개 복사본이다. 마지막 그룹도 삭제할 수 있고, 학생에게는 교사가 그룹을 준비 중이라는 빈 화면을 보여 준다. 복원하면 그룹도 다시 만든다.

휴지통은 해당 브라우저 저장소에 보관한다. 브라우저 데이터를 지우면 복구할 수 없으며, 현재는 같은 게시판을 여러 탭에서 동시에 편집하는 동기화와 다른 기기로 옮기는 보관함을 구현하지 않았다. 30일이 지난 항목은 다음 불러오기 또는 주기적 정리 때 제거한다.

Android 키보드·길게 누르기 미검증 실제 기기 없음. 인앱 브라우저가 모의 터치 입력 명령도 지원하지 않아 통과 판정하지 않음

테스트 과정에서 발견하여 고친 것은 두 가지다. 첫째, 기존 위치 매핑만으로는 구절 전체를 교체할 때 새 문장까지 강조했다. 실제로 지워진 구간을 함께 확인하도록 수정했다. 둘째, 기존 HTML 드래그가 인앱 브라우저에서 그룹을 옮기지 못했다. 포인터를 잡고 실제 놓은 위치를 판단하는 방식으로 바꾸고 그룹·게시글 이동을 다시 확인했다.

4. 가상 참여자

모든 학생과 교사는 프로그램 사용 초보다. 차이는 디지털 숙련도가 아니라 글쓰기 상황과 도움의 필요 정도로 설정했다.

역할 설정 살펴볼 상황
도토 선생님 초등 담임, PC 사용, 새 프로그램에 익숙하지 않음 전체 원고 보기, 구절 피드백, 그룹 정리·복원
김하늘 생각은 풍부하지만 평가 표현이 막연함 ‘좋다’에 이유 붙이기, 피드백 읽고 고치기
이지우 다른 친구의 반응을 궁금해함 게시판 읽기와 댓글, 미게시·게시 구분
박서준 먼저 쓰다가 그룹·출처를 놓침 다른 그룹으로 옮기기, 출처 보완
최유나 자기 의견을 말로 설명하는 것을 좋아함 친구 의견 읽기, 구체적인 질문 댓글

한소은 첫 문장을 시작하는 데 도움이 필요함 빈 원고의 부담, 짧은 문장 틀의 필요

5. 수업 A — 서평 쓰기

게시판은 ‘우리 반이 권하는 책’, 그룹은 ‘추천하고 싶은 책 / 다른 생각이 든 책’으로 설정했다. 공통 텍스트는 이번 검토를 위해 쓴 창작 동화 『비를 나누는 우산』이다. 실제 출판 도서를 읽었다고 가정하지 않았다.

학생 만든 원고 최종 화면 상태
김하늘 작은 우산이 준 큰 마음 게시. 교사의 구절 피드백을 읽고 자기 경험을 넣어 수정·재게시
이지우 나도 우산을 나눠 줄래 게시. 하늘의 글에 이유가 구체적이라는 댓글과 질문 작성
박서준 친절 뒤의 이야기도 궁금해 게시. 처음 선택한 추천 그룹에서 다른 생각 그룹으로 교사가 이동
최유나 고맙다는 말은 바로 해도 좋아 게시. 쪽지를 쓰는 행동에 대한 다른 관점 제시
정도윤 비 오는 날 친구 두 문장의 미게시 초안
한소은 친구에게 권하는 책 첫 문장이 진행 중인 미게시 초안

실제 조작한 흐름은 그룹 + → 원고 작성 → 게시/초안 유지 → 교사 전체 글에서 6개 원고 열람 → 구절 선택·피드백 → 학생이 고쳐 쓰고 재게시 → 친구 댓글이다.

  • 수정 전: “이 책은 정말 좋다.”
  • 교사의 가상 발문: “어떤 점이 좋았나요? 우산을 기울인 장면과 내 경험을 연결해 한 문장 더 써 볼까요?”
  • 수정 후: “나도 우산이 없던 날 친구의 도움을 받은 적이 있어서 그 장면이 더 따뜻하게 느껴졌다.”
  • 친구의 가상 댓글: “내 경험을 넣어서 왜 좋았는지 더 잘 알겠어. 어떤 친구에게 권하고 싶니?”

이 장면은 제품이 글의 근거를 구체화하는 수업을 담을 수 있음을 보여 준다. 학생이 스스로 학습 효과를 얻었다는 실증 자료는 아니다. 또한 전체 교체 후 ‘대상 구절 삭제됨’이라는 상태만 있으면 아이가 고쳐 쓴 일을 잘못한 것으로 오해할 가능성이 있다.

6. 수업 B — 국가유산 조사하여 글 쓰기

게시판은 ‘우리 손으로 소개하는 국가유산’, 그룹은 ‘수원 화성 / 경주 첨성대’로 설정했다. 국가유산포털의 공식 소개를 바탕으로 짧은 가상 조사 글을 구성했다.

학생 만든 원고 최종 화면 상태
김하늘 돌을 들어 올린 지혜 수원 화성 그룹에 게시. 축성 시기·도구와 보존 의견을 구분
이지우 하늘을 살핀 옛사람들 첨성대 그룹에 게시. 위치·건립 추정을 소개
박서준 수원 화성의 가치 출처 없이 게시한 뒤, 교사의 피드백을 읽고 기관·자료명·날짜 추가 후 재게시
최유나 첨성대는 왜 소중할까 게시. 서준의 글에 거중기 모습을 궁금해하는 댓글 작성
정도윤 정조와 수원 화성 더 조사할 질문을 포함한 미게시 초안
한소은 경주에서 만나는 첨성대 이름·위치를 적은 미게시 초안
  • 교사의 가상 발문: “자료를 어디에서 읽었나요? 글 끝에 기관 이름, 자료 제목, 읽은 날짜를 적어 주세요. 자료 문장을 그대로 옮겼다면 내 말로 바꿔 봅시다.”
  • 보완한 내용: “출처: 국가유산청 국가유산포털, ‘수원 화성’ 소개. 읽은 날: 2026년 9월 5일.”
  • 친구의 가상 댓글: “거중기가 어떤 모습인지 궁금해. 다음에는 사진을 함께 보고 싶어.”

현재 앱에서는 출처를 본문에 직접 적는다. 자료 링크를 나눠 주는 곳, 출처 전용 입력 칸, 그림·사진 첨부는 없다. 초보 학생에게 웹주소 복사·탭 전환·본문 붙여넣기를 모두 맡기는 것보다 교사 자료함이나 간단한 출처 틀이 먼저 필요하다는 가설을 얻었다. 사진 첨부는 도움이 되지만 첫 개선의 필수 조건으로 보지는 않는다.

7. 가상 교사·학생의 예상 피드백

아래 따옴표 안 발언은 AI가 구성한 가상 발언이다. ‘화면 관찰’은 실제 UI에서 본 것, ‘예상’은 초보 사용자의 반응에 관한 가설을 뜻한다.

가상 발언 근거와 성격 개선 제안
교사: “글을 안 만든 아이도 들어왔는지 알고 싶어요.” 화면 관찰: 원고가 없는 수업은 연결 인원도 0으로 표시하는 시안임. 실제 참가자 목록 없음 실제 참가자와 원고 수를 분리. ‘아직 시작 안 함’은 도움을 위한 표시로만 사용
교사: “아직 못 쓴 아이부터 보여 주세요.” 화면 관찰: 그룹 필터·이름순은 있지만 초안/게시/도움 요청 필터 없음 초안·게시됨 필터와 학생이 누르는 도움 요청. 자동 성실도 점수는 불필요
교사: “실수로 지웠어도 돌아오니 안심돼요.” 화면 관찰: 확인창과 휴지통 복원 작동. 심리적 안도는 예상 삭제 대상 수를 유지하고 복원 후 어떤 그룹으로 돌아갔는지 알림
교사: “이 링크를 아이들이 바로 열게 하고 싶어요.” 화면 관찰: 교사 자료함과 링크 배포 UI 없음 교사가 제목 붙인 자료 링크 1–2개 제공. 학생이 긴 주소를 입력하지 않게 함
하늘: “글은 고쳤는데 친구도 새 글을 보고 있나요?” 화면 관찰: 원고 수정과 공개본 업데이트는 별도 버튼 ‘내 원고 저장됨 / 게시판에는 이전 글이 보여요’를 구분. ‘게시글 업데이트’는 ‘고친 글 올리기’로 검토
지우: “이게 저장된 건지 잘 모르겠어요.” 화면 관찰: 본문 아래에는 ‘작성 중’ 표시. 실제 로컬 보관은 구현됨 마지막 저장 상태를 쉬운 말로 표시하고 공개 여부와 혼동하지 않게 함
서준: “다 썼는데 주제를 잘못 눌렀어요.” 실제 연출: 교사가 그룹 이동 메뉴로 옮김. 학생은 직접 이동 못 함 첫 버전은 교사가 이동. 원고 상단 그룹 이름을 명확히 유지하고 이동 요청 통로 검토
유나: “이유를 더 썼는데 피드백이 아직 남아 있어요.” 화면 관찰: 피드백 완료·답장·해결 상태 없음 ‘읽었어요 / 고쳤어요’ 정도의 학생 표시와 교사 확인. 상세 변경 추적은 뒤로 미룸
도윤: “키보드 쓰다가 게시 버튼을 어디서 찾죠?” 화면 관찰: 800×520 편집 영역에서 게시 버튼이 위로 벗어남. Android 자체 키보드는 미검증 글쓰기 핵심 동작을 키보드 위에서 찾기 쉽게 배치. 실제 키보드로 먼저 확인
소은: “첫 줄에 무슨 말을 쓰면 돼요?” 화면 관찰: 제목·본문은 빈 입력 영역, 자동 문장 틀 없음. 막막함은 예상 교사가 선택하는 간단한 질문 3개 또는 시작 문장. 완성 답안 자동 생성은 불필요
조사 수업 학생: “출처에는 주소를 다 써야 해요?” 출처 누락을 의도적으로 연출하고 본문 끝에 보완함 기관/자료 제목/날짜의 짧은 입력 틀, 링크는 선택 입력
조사 수업 학생: “글만 보니까 거중기 모양을 모르겠어요.” 가상 댓글에 넣은 요구. 현재 이미지 첨부 없음 우선 교사 화면·자료 카드로 그림 제공. 학생 이미지 업로드는 후속 검토

8. 다음 개발의 우선순위

순서 제안 완료를 판단할 짧은 기준
실제 수업 전 필수 교사·학생 직접 연결, 권한 확인, 재접속·원고 보관 PC와 실제 태블릿 두 대에서 서로 다른 원고를 쓰고 재접속해 자기 글만 이어 씀
실제 수업 전 필수 Android 화면 키보드·한글 조합·터치 확인 제목→본문→서식→피드백→수정→게시를 실제 키보드로 수행. 입력 손실·커서 점프가 없어야 함
UI 다음 차례 1 저장·공개본 상태와 쉬운 게시 버튼 이름 아이가 ‘나에게 저장됐는지/친구에게 보이는지’를 설명할 수 있음
UI 다음 차례 2 키보드 사용 중 핵심 동작 접근 키보드가 열린 상태에서 현재 문장과 글 올리기 동작을 찾기 쉬움
UI 다음 차례 3 도움 요청·초안/게시 필터·피드백 확인 교사가 손든 학생·초안·피드백 반영 여부를 몇 번의 클릭으로 구분
수업 지원 1 선택형 글쓰기 틀과 출처 칸 서평/조사 글의 시작을 돕되 학생 생각을 대신 써 주지 않음
수업 지원 2 교사 자료 링크·그림 카드 학생이 긴 주소를 입력하거나 여러 검색 탭 사이를 헤매지 않음
나중에 검토 학생 이미지 첨부·수업 템플릿 복제 첫 수업의 입력·연결 문제를 해결한 뒤 현장 필요로 결정

가상 피드백에서 나온 제안을 이번에 모두 구현하지는 않았다. 실제 사용자가 어느 단계에서 멈추는지 확인하기 전에 버튼과 기능을 한꺼번에 늘리지 않는 것이 좋다.

02 · 지도약안

도토 가상 수업 지도약안

2026-09-05 · 초등 5–6학년 기준 · 교사 PC / 학생 태블릿 화면 키보드

교사와 학생 모두 도토 사용이 처음이라는 가정이다. 두 수업은 각각 40분씩 2차시로 계획한다. 아래 시간은 수업 설계 시간이며 실제 수업 시간을 측정한 결과가 아니다. 3–4학년은 글 분량을 3–5문장으로 줄이고 말하기·종이 메모 시간을 늘린다. 1–2학년에게 그대로 적용하는 안은 아니다.

공통 준비와 약속

  • 교사는 수업 전 10분 동안 연습 공간에서 그룹 이름 바꾸기 → 글 열기 → 구절 선택·피드백 → 삭제·휴지통 복원을 한 번 해 본다.
  • 학생은 태블릿을 가로 또는 세로 중 편한 방향으로 놓는다. 외장 키보드를 전제로 하지 않는다. 키보드 열기·숨기기와 문장 끝으로 커서 옮기기를 먼저 연습한다.
  • 첫 연습은 그룹의 + → 제목·한 문장 → 게시판으로 → 이어서 쓰기 네 동작으로 제한한다. 글꼴·색 바꾸기는 필수 활동에서 뺀다.
  • 교사는 화면에 실제로 누를 위치를 가리키며 한 번에 한 동작만 안내한다. 설명하는 동안 학생은 키보드를 잠시 숨긴다.
  • 친구 글은 게시했을 때만 읽는다. 초안을 완성하지 못해도 공개를 강요하지 않는다. 댓글은 ‘좋았던 점 하나 + 궁금한 점 하나’로 쓴다.
  • 학생의 타자 속도나 글자 수를 성취 점수로 쓰지 않는다. 종이에 생각을 먼저 적거나 짝에게 말한 뒤 입력해도 된다.
  • 현재 도토는 한 브라우저의 UI 시안이다. 실제 태블릿 수업은 교사·학생 연결과 재접속·저장을 구현하고 실제 기기 입력을 확인한 뒤 실시한다. 이번 가상 수업의 역할 선택 바는 연습용이며 학생 제품 화면에 추가할 메뉴가 아니다.

1. 서평 쓰기 — 우리 반이 권하는 책

항목 내용
교과·형태 국어, 개인 글쓰기와 짝 읽기
학습 목표 책의 한 장면을 근거로 자기 생각을 밝히고, 친구에게 권하거나 아쉬운 점을 설명하는 짧은 서평을 쓴다.
준비물 미리 읽은 책 또는 아래의 가상 수업용 창작 동화, 종이 메모, 교사 PC·화면, 학생 태블릿
도토 게시판 제목 우리 반이 권하는 책
주제 그룹 추천하고 싶은 책 / 다른 생각이 든 책
학생 산출물 제목 + 5–7문장의 서평 한 편. 입력이 느린 학생은 핵심 3문장부터 쓴다.
글의 순서 책 소개 → 기억에 남는 장면 → 내 생각과 이유 → 권하고 싶은 사람 또는 아쉬운 점

1차시: 읽고 생각하기·도토에 들어가기

단계 시간 교사의 안내 학생 활동·도토 사용
도입 5분 ‘재미있다’는 말만으로 친구가 읽고 싶어질지 이야기한다. 서평과 줄거리 소개의 차이를 말한다.
장면 고르기 10분 장면 하나와 이유 하나를 함께 보여 준다. 책을 읽고 기억에 남는 장면에 종이 표시를 한다.
생각 정리 10분 ‘나는 이 장면이 __해서 __했다’ 문장 틀을 칠판에 쓴다. 짝에게 먼저 말하고 종이에 핵심 낱말 3개를 적는다.
첫 조작 연습 10분 화면 키보드 열기, 그룹 +, 제목 입력, 게시판 복귀를 천천히 시범 보인다. 각자 그룹에서 원고를 만들고 제목과 첫 문장을 쓴다. 초안을 다시 열어 본다.
정리 5분 완성되지 않은 글은 지금 게시하지 않아도 된다고 안내한다. 다음 시간 이어 쓸 문장을 종이 메모로 남긴다.

2차시: 쓰고 고치고 나누기

단계 시간 교사의 안내 학생 활동·도토 사용
다시 열기 5분 새 글 +와 기존 글 ‘이어서 쓰기’를 구분한다. 자기 초안을 다시 연다.
초안 쓰기 13분 교사 전체 글에서 막힌 학생을 찾아 짧은 질문을 준다. 화면 키보드로 서평을 쓴다. 서식은 기본값을 쓴다.
한 가지 고치기 10분 ‘정말 좋다’ 같은 구절을 선택하고 구체적인 질문 하나를 남긴다. 피드백 목록·노란 구절을 읽고 이유나 경험을 한 문장 보탠다.
공유 8분 게시 여부를 학생이 고르게 하고 짝의 글을 읽도록 한다. 게시 후 친구 글 한 편에 다정한 댓글을 남긴다.
정리 4분 무엇을 고쳤는지 말로 묻는다. 수정 전후 차이를 말한다. 게시 후 더 고쳤다면 ‘게시글 업데이트’를 누른다.

교사 피드백 예: “어떤 점이 좋았나요? 우산을 기울인 장면과 내 경험을 연결해 한 문장 더 써 볼까요?”

관찰 기준은 ① 책의 구체적인 장면을 언급했는가 ② 자기 생각에 이유가 있는가 ③ 피드백을 읽고 한 부분을 고쳤는가이다. 긴 글·화려한 글꼴·빠른 게시를 보상하지 않는다.

가상 수업용 창작 동화: 비를 나누는 우산

하늘이는 학교 현관에서 운동장을 바라보았다. 아침에 맑았던 하늘에서 비가 쏟아졌다. 가방에는 우산이 없었다. 친구들이 하나둘 떠난 뒤 지우가 노란 우산을 펴고 다가왔다.

“큰길까지 같이 갈래?” 하늘이는 말없이 고개를 끄덕였다. 둘이 쓰기에는 우산이 조금 작았다. 지우는 하늘이 쪽으로 우산을 기울였다. 하늘이는 지우의 한쪽 어깨가 젖는 것을 보았다. 우산 손잡이를 가운데로 조금 옮기자 이번에는 두 아이의 소매 끝에 작은 물방울이 맺혔다.

큰길에서 헤어질 때 하늘이는 고맙다는 말을 작게 했다. 집에 와서는 공책 한쪽에 노란 우산을 그렸다. 다음 날, 지우의 책상에 ‘어제는 네 덕분에 비 오는 길이 덜 무서웠어’라고 쓴 쪽지를 놓았다. 지우가 웃으며 쪽지를 접었다. 쉬는 시간에 둘은 창가에서 오늘의 하늘을 함께 올려다보았다.

이 동화는 이번 가상 수업을 위해 만든 창작 예시이며 실제 출판된 도서가 아니다. 실제 서평 수업에서는 학급이 읽은 책으로 바꾼다.

2. 국가유산 조사 글 쓰기 — 우리 손으로 소개하는 국가유산

항목 내용
교과·형태 사회·국어 통합, 짝 조사 후 개인 글쓰기
학습 목표 믿을 수 있는 자료에서 확인한 사실 두 가지와 자기 생각을 구분하고, 출처를 적어 국가유산 소개 글을 쓴다.
준비물 교사가 고른 공식 소개 자료 2개, 쉬운 말로 정리한 종이 자료, 출처 메모 칸, 학생 태블릿
도토 게시판 제목 우리 손으로 소개하는 국가유산

학생 산출물 이름·위치, 사실 두 가지, 소중한 이유, 출처를 포함한 5–7문장. 느린 학생은 사실 하나부터 쓴다.

자료 읽기 시범 8분 검색 결과의 첫 문장을 복사하는 대신 기관과 자료 제목을 확인하는 모습을 보여 준다. 공식 자료에서 이름·위치를 찾아 표시한다.

공유 8분 글을 같은 유산 그룹끼리 읽게 한다. 게시하고 친구 글에 새롭게 안 점·질문 한 가지를 댓글로 쓴다.
정리 4분 사실과 자신의 보존 의견을 각각 한 가지 묻는다. 오늘 알게 된 사실과 유산을 대하는 태도를 말한다.

관찰 기준은 ① 자료로 확인한 사실이 있는가 ② 원문의 어려운 표현을 이해하고 자기 말로 썼는가 ③ 출처가 적혀 있는가 ④ 보존에 관한 자기 생각이 있는가이다. 현재 앱에는 출처 전용 칸·이미지 첨부·자료 배포 기능이 없으므로, 이번 수업에서는 출처를 본문 끝에 적고 자료는 교사 화면·종이 자료로 제공한다.

사용할 공식 자료

  • 국가유산포털: 수원 화성: 1794–1796년 축성, 거중기 등 축성 도구를 확인하는 자료.
  • 국가유산포털: 경주 첨성대: 위치와 천문 관측 관련 해설, 선덕여왕 시기 건립 추정을 확인하는 자료. 자료의 ‘추정’ 표현을 확정 사실로 고쳐 쓰지 않는다.

교사는 긴 웹주소를 학생이 직접 입력하게 하지 않는다. 자료를 열어 주거나 종이 자료 하단에 기관·제목·확인 날짜를 적어 준다. 웹페이지와 글쓰기 화면을 계속 오가는 일이 조사 활동보다 어려워지지 않게 한다.
