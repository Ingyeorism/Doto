# 도토 · 우리 반 글쓰기

학생은 태블릿에서 글을 쓰고, 교사는 반 전체의 **작성 중인 본문**을 보면서 바로 고치거나 피드백합니다. 완성 글은 주제별 게시판에 올리고 친구들과 댓글을 나눕니다.

학생망에 연결된 태블릿 하나에서 수업을 열고, 같은 입장 화면에 교사용 코드를 입력한 PC에서도 수업을 진행할 수 있습니다. 태블릿과 PC는 같은 교사 화면을 사용합니다. 기존처럼 PC에서 직접 수업을 열어도 됩니다.

**수업을 연 기기의 도토 화면이 열린 동안 수업이 운영됩니다.** 원고·피드백·개인 메시지는 이 기기를 중심으로 WebRTC로 전송하고, 중앙 서버는 웹 화면·방 코드·접속 신호만 담당합니다. 중앙 서버에는 문서를 저장하지 않습니다.

## 이 PC에서 열기

1. Node.js 22.22 이상이 설치된 PC에서 **도토 열기.cmd**를 더블클릭합니다.
2. 자동으로 패키지와 화면을 준비하고 [교사 시작 화면](http://localhost:3000/teacher/start)을 엽니다.
3. **수업 열기 → 수업 이름 → 방 열고 코드 받기**를 누르면 빈 수업과 ‘우리 반 이야기’ 그룹 하나, 실제 교사용·학생용 입장 코드가 만들어집니다.
4. 수업을 연 기기에서 **수업 마치기**를 누르고 확인하면 수업을 마칩니다. 원격 교사 PC의 **PC 연결 나가기**는 수업을 끝내지 않습니다.
5. 이 PC의 서버까지 끄려면 **도토 서버 종료.cmd**를 실행합니다. 보관한 글은 브라우저에 남습니다.

서버가 이미 켜져 있으면 화면만 엽니다. 코드를 수정한 뒤에는 서버를 종료하고 다시 열어 최신 버전을 적용하세요. 실행 출력은 `.doto.log`, 연결 진단 기록은 `logs/doto.jsonl`에 있습니다.

`localhost`는 이 PC에서 확인하는 주소입니다. 여러 기기가 함께 사용할 실제 수업에는 아래 절차로 **HTTPS 주소**를 준비합니다. 태블릿에도 기존 도토 주소를 열면 되며, 별도 서버 앱을 설치하지 않습니다.

HTTPS를 준비하기 전 같은 네트워크에서 임시로 연결할 때는 모든 기기에서 `http://<도토를 실행한 PC의 IP 주소>:3000`을 엽니다. 이 경우에도 수업을 여는 기기는 태블릿일 수 있습니다. HTTP에서는 화면 꺼짐 방지를 기기 설정에서 직접 해야 합니다. UUID는 `crypto.getRandomValues()` 기반 생성 방식으로 자동 전환합니다.

## 수업에서 쓰는 방법

- **수업을 여는 기기:** `/teacher/start`에서 **수업 열기**를 선택합니다. 서버 관리 화면 왼쪽의 8자리 코드는 교사 PC에서, 오른쪽의 6자리 코드는 학생들이 사용합니다. **전체 글 · 게시판**으로 이동하면 태블릿에서도 수정·피드백·그룹 관리가 가능합니다.
- **교사 PC:** 같은 도토 주소의 **방 입장하기**에서 교사용 코드를 입력합니다. 학생 이름 입력 없이 교사 화면으로 연결되며, PC를 나가도 태블릿의 수업은 유지됩니다.
- **학생:** 같은 **방 입장하기**에서 학생용 코드와 이름 입력 → 게시판의 그룹 **+** → 글쓰기. `/student/join`, `/teacher/join`의 기존 주소도 같은 통합 입장 화면으로 연결됩니다. 학생용 QR에는 학생 코드만 포함합니다.
- **태블릿 화면 유지:** 방을 열면 화면 꺼짐 방지를 요청하고 실제 허용 결과를 표시합니다. **어둡게 켜 두기**는 도토 화면을 어둡게 바꾸면서 수업을 유지합니다. 기기를 잠그거나 다른 앱으로 전환하는 기능이 아닙니다. 화면 유지가 허용되지 않으면 기기 설정에서 자동 잠금을 꺼 주세요. 배터리 정보를 읽을 수 없는 브라우저에는 가짜 수치 대신 **기기에서 확인**을 표시합니다.
- **이어 쓰기:** 글쓰기에서 **게시판으로** 나가면 초안을 이 기기에 저장합니다. 게시판 위쪽의 **내가 쓰던 글 → 이어 쓰기**로 다시 열 수 있고, 같은 브라우저에서 새로고침해도 이어집니다. 미완성 원고는 교사에게도 계속 보입니다.
- **피드백:** 원고를 열고 문장을 드래그 → **피드백 하기**. 글 전체 메시지와 **직접 수정**도 가능합니다. 교사 상세 화면을 새로고침하면 같은 원고가 다시 열리며, 게시판의 완성 글을 열어도 교사와 작성 학생은 개인 피드백을 볼 수 있습니다.
- **줄간격:** 기본 160%이며 도구의 **더 보기 → 줄간격**에서 60~300%를 선택합니다. Enter 문단 사이에 추가 여백이 없으며 여러 번 입력한 빈 줄도 읽기 화면에 그대로 보입니다.
- **공개:** **게시하기**는 누른 순간의 완성본을 게시하고 완료 후 게시판으로 이동합니다. 이후 수정은 **수정한 글 게시하기**로 반영하며 댓글은 유지됩니다.
- **펼치기:** 게시판 카드의 **펼치기 / 접기**로 글 전체를 읽습니다. 교사는 **그룹 설정 → 게시글 자동으로 펼치기**로 학생에게도 같은 기본 보기를 적용합니다.
- **도움·질문:** 학생은 **선생님께 도움 요청** 또는 **메시지 보내기**를 누릅니다. 도움 요청은 해당 글에만 표시되고, 교사 화면의 팝업에서 **요청한 글 보기**로 바로 열 수 있습니다. **나중에 보기**로 팝업을 닫아도 요청은 남습니다. 교사는 전체 글의 **도움 요청 / 새 메시지**로 찾고, 원고 상세의 대화에서 답장합니다. 학생은 메시지 버튼의 새 답장 배지를 눌러 읽습니다.
- **그룹:** 교사가 그룹·추가자료·생각 질문을 준비합니다. 서평·조사 예시는 흐린 안내로만 보이며 질문 입력값을 자동으로 채우지 않습니다. 게시판 글은 놓은 위치로 이동하고 같은 그룹 안에서도 드래그로 순서를 바꿉니다. 삭제한 그룹과 원고·피드백·댓글은 휴지통에서 30일 동안 복원합니다.
- **재입장:** 같은 브라우저는 자기 원고를 이어 씁니다. 이름이 같아도 다른 학생의 원고를 가져오지 않습니다. 공용 태블릿의 사용자가 바뀌면 **다른 이름으로 새로 입장**을 선택합니다.

다른 학생의 미게시 원고와 개인 피드백은 전송하지 않습니다. 학생은 자기 댓글을 지울 수 있고 교사는 모든 댓글을 삭제하거나 댓글 작성을 잠글 수 있습니다.

### 이용약관과 개인정보 안내

방 열기·입장 및 지난 수업 다시 열기 버튼 가까이에 동의 안내를 표시합니다. **자세히 읽기**는 선택 사항이며, 별도 체크나 끝까지 읽기 없이 해당 버튼(또는 입력란의 Enter)으로 동의하고 진행합니다. 시작 화면의 **이용약관 · 개인정보 안내**에서도 내용을 볼 수 있습니다. 안내를 열거나 닫는 동작만으로는 동의가 기록되지 않습니다.

버튼을 누르면 안내 버전·시각·동작(`create` / `join`)만 `doto.usage-consent`에 최근 기록 하나로 저장합니다. 이름·방 코드가 없는 이 브라우저의 확인 기록이며 서버에 전송하지 않습니다. 저장소를 사용할 수 없어도 추가 확인으로 입장을 막지 않습니다. 실제 공유·저장 범위, 진단 기록, 삭제 요청 방법을 안내에 담았습니다.

이 간단한 버튼 동의는 학교의 개인정보 처리 절차나 법정대리인 동의를 확인하는 기능이 아닙니다. 만 14세 미만 학생의 개인정보 처리에 동의가 필요한 경우에는 수업 운영자가 별도 절차를 준비해야 합니다. [개인정보 보호법 제22조의2](https://www.law.go.kr/LSW/lsLinkCommonInfo.do?chrClsCd=010202&lsJoLnkSeq=1006183947)

## 저장과 지난 수업

**저장 중 / 이 기기에 저장됨 / 저장하지 못했어요**는 실제 IndexedDB 저장 결과입니다. 연결이 끊긴 동안 쓴 글은 자기 기기에 남으며, 교사에게 아직 전달되지 않았다는 안내를 보여 줍니다. **다시 연결**하면 양쪽 수정 사항을 합칩니다.

수업을 연 기기와 교사 PC·학생 모두 같은 탭을 새로고침하면 자기 연결 정보로 복귀합니다. 서버는 수업을 연 기기가 잠깐 나간 방을 약 5분 유지합니다. 서버 재시작으로 방이 사라졌다면 수업을 연 기기에서 다시 연결하거나 **지난 수업 → 다시 수업 열기**로 새 코드를 받습니다.

수업 전체 보관함은 **수업을 연 기기**에 남습니다. 원격 교사 PC에는 별도의 수업 사본을 저장하며 호스트와 학생의 재입장 토큰을 전달하지 않습니다. 교사 PC는 수업 호스트를 대신 이어받지 않습니다. **코드 새로 만들기**는 이후 교사 입장에 쓸 코드를 바꾸며, 이미 연결된 PC와 해당 기기의 재입장 권한은 유지합니다.

**결과 내보내기**로 HTML 파일 하나를 받습니다. 현재 원고·개인 피드백·학생과 교사의 대화·게시한 완성본·댓글·출처·휴지통 보관 글을 브라우저에서 읽고 인쇄할 수 있습니다. 재가져오기 기능은 없습니다.

보관함은 **사용한 브라우저와 웹주소**에 속합니다. 브라우저 데이터를 지우거나 다른 PC·브라우저·주소로 이동하면 기존 목록이 나타나지 않습니다. 필요한 수업은 HTML로 간직해 주세요.

## 서버에 설치하기

실제 N100의 OS·도메인·접속 정보는 아직 확인되지 않았습니다. 다음은 **Docker Compose가 설치된 서버용 배포 묶음**입니다.

1. 프로젝트를 서버로 복사합니다.
2. `.env.example`을 `.env`로 복사하고 `DOMAIN`을 실제 도메인으로 바꿉니다. `PUBLIC_URL`도 `https://`로 시작하는 같은 주소로 맞춥니다.
3. 도메인의 DNS가 서버를 가리키도록 하고, 공유기·방화벽에서 80/443을 서버에 연결합니다. 이 최초 설정은 운영자만 합니다.
4. 프로젝트 폴더에서 실행합니다.

```sh
docker compose up -d --build
```

교사와 학생은 설정한 HTTPS 주소를 엽니다. 앱과 HTTPS 처리를 하나의 Compose 묶음으로 시작하며 Caddy가 인증서를 자동 발급·갱신합니다. 문서를 중계하는 서버는 포함하지 않습니다. [Caddy 자동 HTTPS 공식 안내](https://caddyserver.com/docs/automatic-https)

```sh
docker compose stop             # 서버 종료
docker compose start            # 다시 시작
docker compose logs --tail=50   # 실행 상태 확인
```

서버 재부팅 시 Docker가 자동 실행되면 도토도 자동으로 시작합니다. 업데이트는 `docker compose up -d --build`를 실행합니다.

이미 HTTPS 웹서버가 있는 경우:

```sh
npm ci
npm run build
npm start
```

3000 포트로 기존 HTTPS 웹서버에서 `/`와 `/signal` WebSocket을 연결합니다. `.env`의 `PUBLIC_URL`에 실제 HTTPS 주소를 적습니다. 기존 80/443 구성이 있다면 Compose의 Caddy를 중복 실행하지 않습니다. OS에 따른 자동 실행 설정은 서버 환경을 확인한 뒤 적용합니다.

## 연결이 안 되면

약 20초 안에 직접 연결을 맺지 못하면 실패 안내와 **다시 연결**을 보여 줍니다. 수업을 연 기기의 도토 화면과 인터넷 연결을 확인하고 다시 누르세요. 학생망과 교사 PC 사이에 직접 연결이 허용되어야 합니다. 같은 와이파이에서도 기기 간 통신을 차단하면 연결할 수 없습니다. TURN·터널·WebSocket 문서 중계로 전환하는 기능은 없습니다.

**새 입장 잠금**은 신규 입장만 막고 기존 학생의 재입장은 허용합니다. 학생이 태블릿을 바꾸면 새 참가자로 들어옵니다.

### 연결 진단 로그

서버와 교사·학생 브라우저의 연결 기록을 `logs/doto.jsonl`에 JSON 한 줄씩 자동 저장합니다. 기본 5 MiB마다 순환하고 현재 파일과 `.1`~`.4`까지 총 5개(약 25 MiB)를 유지합니다. `.env`의 `LOG_DIR`, `LOG_MAX_BYTES`, `LOG_FILES`로 변경합니다. Docker에서는 `doto_logs` 볼륨에 유지됩니다.

- 입장 요청·교사 접속 여부·신호 전달/누락·WebSocket 종료 코드·하트비트 실패를 기록합니다.
- 브라우저에서는 연결 시도별 ID, SDP 종류(offer/answer), 양쪽 ICE 후보 종류와 개수·오류 코드·상태 변화, DataChannel 열림/끊김, 20초 대기 초과, 선택된 연결 경로의 통계, 저장 실패·페이지 숨김·네트워크 변경을 기록합니다. 연결 준비 중에는 5초, 연결된 뒤에는 30초마다 통계를 남깁니다. `ice.candidate`의 `candidateType`은 내 후보, `remoteCandidateType`은 상대 후보입니다. 종료로 통계를 읽을 수 없으면 빈 통계 대신 `peer.stats_failed`로 표시합니다.
- `time`은 서버 수신 UTC 시각, `clientTime`은 기기 UTC 시각입니다. `clientId`·`attemptId`·`requestId`로 양쪽 기록을 연결합니다. 재전송된 같은 `eventId`는 같은 사건입니다. 업로드 시점과 발생 시점이 다를 수 있습니다.
- 브라우저는 2초마다(40개 이상 쌓이면 바로) 모아 전송하고 실패 시 최대 60초 간격으로 재시도합니다. 최근 기록과 미전송 기록을 각각 최대 1,000개까지 해당 탭의 세션 저장소에 보관합니다. 저장소 쓰기는 0.1초 단위로 모읍니다. 같은 탭 새로고침에는 유지되지만 탭 삭제·브라우저 데이터 삭제·갑작스러운 종료 또는 한도 초과로 기록이 사라질 수 있습니다. 페이지를 숨길 때도 전송을 시도합니다.
- 연결 실패 안내와 교사 **수업 설정 → 진단 로그 저장**에서 해당 기기의 최근 기록을 내려받을 수 있습니다. 서버에 연결하지 못해도 사용할 수 있습니다.
- 학생 이름·입장 코드·재입장 토큰·본문·피드백·메시지·원본 SDP·후보 IP 주소·오류 원문은 기록하지 않습니다. 허용한 연결 메타데이터만 서버에서 다시 걸러 저장합니다.

수집 상태는 `/api/health`의 `logging.writable`, `logging.written`, `logging.clientEvents`로 확인합니다. `writable: false`이면 로그 폴더 권한·저장 공간을 확인합니다. 이전 버전 브라우저에는 진단 기능이 없으므로 서버를 업데이트한 뒤 **교사와 학생 화면을 모두 새로고침**해야 합니다.

```powershell
Get-Content logs/doto.jsonl -Tail 80
Get-Content logs/doto.jsonl -Wait
```

외부망 접속 실패 시 교사와 학생 양쪽을 새로고침하고 새 입장 코드로 한 번 시도한 뒤 발생 시각을 기록하면 입장·신호 교환·직접 연결 중 실패 단계를 확인할 수 있습니다. 기존에 남기지 않은 로그를 소급 복구할 수는 없습니다.

## 개발과 확인

```sh
npm ci
npm run dev                 # 화면과 연결 서버를 한 번에 실행

node --experimental-strip-types scripts/smoke-trash.mjs
node --experimental-strip-types scripts/smoke-learning.mjs
```

## 이전 시안과 가상 수업

**도토 UI 열기.cmd**는 이전 시안을 `?preview=1`로 엽니다. `?simulation=review`와 `?simulation=heritage`도 별도로 유지합니다. 이 모드들은 실제 기기 연결을 사용하지 않습니다.

**도토 태블릿 시안 열기.cmd**와 `?preview=tablet`도 화면 검토용 예시로 남겨 두었습니다. 실제 수업은 **도토 열기.cmd** 또는 `npm run dev`로 실행하고, 주소에 `preview`를 붙이지 않습니다. 5173 포트의 `npm run ui`에는 연결 서버가 없습니다.
